# AgileNest 前端视觉与交互实施指南

本页只规定视觉与交互实施标准。业务规则见 [DESIGN](DESIGN.md)，公开接口与 Owner 见 [TEAM](TEAM.md)，实际通过范围见 [UX](UX.md)，外部产品来源及采用取舍统一见 [PR-RESEARCH](PR-RESEARCH.md)。下列尺寸、主题与可访问性目标不是全页面实测结论。

## 页面信息层级

以飞书日常协作为主参考，结合 Linear 的工作密度、Plane 的详情分层及 GitHub 的事项组织。通用项目不必以代码为中心。

| 页面类型 | 首屏与布局重点 |
|---|---|
| 登录 | 桌面左侧校园拼贴与功能速览、右侧表单；窄屏表单优先，独立山海全景与自然排列的功能卡片；校徽、字段标签、密码显隐、失败保留与飞书入口清晰 |
| 工作台/项目概览 | 真实待处理事项、目标与下一步；避免无来源健康分、模拟趋势和大型欢迎卡 |
| 团队与成员 | 目录、公告、分工分区；职务说明先于学术资料，入口对应当前能力 |
| 任务池/看板/表格 | 工具栏、已选条件与任务内容；相同数据的视图切换位置稳定 |
| 任务详情/验收 | 正文、属性、成果版本、历史与操作区分层；复杂编辑进入完整页 |
| 资料库 | 分类/主题目录与内容分栏，路径和当前位置始终明确 |
| 阶段交付 | 成果证据、清单与问题分区；当前记录版本与确认结果可辨 |
| 日历 | 清楚区分本人安排与项目事项；日期导航和当天内容相互对应 |
| 协作面板 | 一个右下角入口，消息与本地草稿切换；真实未读数、来源和偏好可达 |

功能名称作标题，姓名用于账号和成员识别。列表用分隔、任务用卡片，避免卡片层层嵌套；长标题在详情完整可读。空状态说明缺少什么及可执行动作，筛选为空提供清除入口；反馈只描述已保存、已提交等事实。

## 视觉系统

沿用 `globals.css` 唯一 tokens 和共享 UI，Lucide 图标保持统一尺寸/线宽。

| 元素 | 标准 |
|---|---|
| 品牌 | 浅色 `#294a78`，深色 `#92b6e8`；少量暖橙 `#bf6a34` / `#e6a16d` |
| 页面/内容面 | 浅色 `#f5f7fb` / 白色；深色 `#141a23` / `#1b2330` |
| 状态 | 复用 `StatusPill`，文字与语义色同时出现 |
| 字阶 | 页面 24/32，分区 16/24，正文 14/22，辅助 12/18；关键业务文字不缩为 10px |
| 间距 | 4/8/12/16/24/32px；工作页面桌面 24px、窄屏 16px |
| 控件 | 输入与按钮 36–40px，触屏有效点击区约 44px；圆角 8–12px |
| 看板/表格 | 列宽约 260–300px，表格约 48px 行高，仅局部横滚 |
| 详情 | 抽屉约 600–680px，当前共享实现 660px；窄屏全宽，头/底稳定、中间滚动 |
| 动效 | hover 120–160ms，普通面板 180–220ms，抽屉 220–300ms；遵循系统减少动效偏好 |

数值与版本用等宽数字；焦点和错误可见，成功沿用轻提示。目录与表单窄屏转上下布局，不通过缩小关键文字强行塞入。

登录宣传区使用局部浅蓝/深海军蓝视觉：浅蓝 `#c7e5f4`、强调蓝 `#87bfdf`、文字和主要操作 `#143c60`、内容面 `#f5faff`，外框 `#102e4b` 加强深浅层次。仅在共享 auth 组件的 CSS Module 内定义，业务页面继续沿用全局品牌和五态 tokens。桌面建南大会堂拼贴与手机山海校园全景分别生成，picture 在 999px 断点选择独立资源；手机功能介绍自然排列，避免大幅海报裁切。校徽使用官网原图并保持比例；文字、字段和功能切换仍是可访问的真实 HTML，不烘焙入图片。资源与来源见[登录设计记录](design/login-rc17/README.md)。

## 交互实施标准

### 导航、筛选与版本

- 视图切换保留合法 URL 条件；清除单项、全部重置与保存本人视图分别明确。分享链接仍由服务端校验权限。
- 详情使用已登记的深链接参数，关闭只移除详情参数并恢复焦点；任务不在当前筛选时说明详情来源。
- 当前阅读版本、当前可操作版本与只读历史明确区分。缺失来源版本时提示缺失，不用最新正文冒充历史。
- 目录面包屑、名称选择与当前位置创建/上传保持一致；危险操作确认说明范围，恢复结果显示原位置。

### 表单、文件与反馈

- 按真实姓名选择成员，不让用户填写数据库 ID；展示能力来源或由谁继续处理，前端不另设权限开关。
- 操作按钮和拖动入口消费同一公开能力/转移结果；拖动不能跳过补充表单或确认，失败/取消保留原列。
- 等待显示 `aria-busy` 并防重复；失败保留正文、选择、附件和原版本。409 提示已有更新，明确采用最新版本后再继续写入。
- 草稿按账号和对象隔离；保存失败提供可复制提示。离开、Esc 或背景点击不得悄悄丢失正文，放弃修改需确认。
- 多文件上传逐份显示等待/处理中/成功/失败，失败单独重试；不伪造百分比。文件正文、讨论附件和正式成果的选择语境清楚。
- 错误留在相关输入或操作附近，使用文字和图标；成功提示可关闭，刷新后结果可核对。

### 浮层与消息

- 消息和本地草稿共用协作入口，面板互斥；详情/表单层级更高，避免遮挡主要操作与反馈。
- 未读角标与短时预览来自真实数据；气泡消失不等于已读，偏好提供恢复入口，错误有就近重试。
- AI 按当前真实连接与权限展示状态，不生成模拟回答、虚假通知或执行成功承诺；规划与改进建议经本人预览和明确确认后采用，存储及工具边界见 AI 文档。

## 响应式与可访问性

- 390px 视口先检查整页溢出；复杂表格/看板局部滚动，长内容和目录保持关闭/返回入口可见。
- 弹窗复用现有 Radix 焦点环路，标题/说明齐全；重要确认默认可安全取消，Tab/Shift+Tab 限定弹窗内，Esc 返回合理触发位置。
- 图标按钮有可读名称，拖动具备等价按钮路径；颜色之外提供状态文字、图标或说明。
- 正文对比度目标 4.5:1，关键焦点/边界目标 3:1，必须在实际深浅背景核验。动态反馈使用 status，不将所有静态标签设为播报。
- 系统减少动效偏好关闭非必要动画，避免依赖动画表达业务结果。

## Agent 交付要求

先读 AGENTS 当前范围与 TEAM 契约，确认分支、基线、Owner 和已有修改。派工说明给出允许文件、提供/消费的公开入口、权限与失败要求、实际交付和检查范围；共享 schema、TEAM 与版本由 root 串行集成，不让多位 agent 改同一文件。

报告区分已实现、实际检查与未检项；概念稿和历史截图不能作为当前实装验收证据。逐轮版本流水保留于 [CHANGELOG](../CHANGELOG.md)，未来能力只列 [ROADMAP](ROADMAP.md)，不在本指南重复业务状态机或发布过程。
