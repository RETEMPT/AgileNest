# AgileNest 前端视觉与交互实施指南

当前方向：飞书日常协作、Linear 的工作密度、Plane 的内容详情与 GitHub 的任务组织。实际能力见 [协作工作区](COLLABORATION-WORKSPACE.md)，模块接口见 [TEAM](TEAM.md)，历史实测见 [UX](UX.md)。下列尺寸与可访问性是实施标准，完整多端验收按用户最终要求执行。

## 页面职责

| 页面 | 首屏重点 | 主要入口 |
|---|---|---|
| 工作台 | 本人待执行、待修改、待验收事项 | 打开任务，继续处理 |
| 团队空间 | 成员分工、公告、项目目录 | 创建/分类项目、管理成员与团队资料 |
| 项目概览 | 目标、当前节点、五步协作路径与风险 | 进入任务、项目资料、验收 |
| 任务池/看板/表格 | 同一份任务与同一套筛选 | 新建、按职务认领/指派、详情、保存视图 |
| 任务详情 | 目标、标签/依赖、来源、讨论、成果版本 | 执行与逐项验收；复杂编辑进入完整页 |
| 资料库 | 目录、分类、搜索、文档与原文件 | 正文、评论、互链、协作者、创建行动项 |
| 验收台 | 指定提交版本的证据和逐项意见 | 通过、打回，保留历史 |
| 个人/项目日历 | 清楚区分本人安排和项目任务 | 本人提醒，项目日期与里程碑 |
| 通知中心/协作 bot | 本人真实未读消息、来源 | 阅读、已读、直达事项、通知偏好 |

执行、协调、验收是信息视角，由本人职务和项目场景计算入口，不增加独立的前端权限开关。学术身份只展示。概览不要用无来源健康分、模拟趋势和大幅欢迎卡替代待处理内容。

## 视觉系统

沿用 `globals.css` 唯一 tokens 与共享 UI，Lucide 图标保持统一尺寸/线宽。

| 元素 | 标准 |
|---|---|
| 品牌 | 浅色 `#294a78`，深色 `#92b6e8`；少量暖橙 `#bf6a34` / `#e6a16d` |
| 页面/内容面 | 浅色 `#f5f7fb` / 白色；深色 `#141a23` / `#1b2330` |
| 状态 | 五态由 `StatusPill` 表达，文字与语义色同时出现 |
| 字阶 | 页面 24/32，分区 16/24，正文 14/22，辅助 12/18；关键业务文字不缩为 10px |
| 间距 | 4/8/12/16/24/32px；工作页面桌面 24px、窄屏 16px |
| 控件 | 输入与按钮 36–40px，触屏有效点击区约 44px；常用圆角 8–12px |
| 看板/表格 | 列宽约 260–300px；表格约 48px 行高；仅局部横滚 |
| 详情 | 抽屉约 600–680px，当前共享实现 660px；窄屏全宽，固定头/底、中间滚动 |
| 动效 | hover 120–160ms，普通面板 180–220ms，抽屉 220–300ms；尊重减少动效 |

标题、正文、属性和历史有明确层级；目录与内容分栏，窄屏转上下布局。列表用分隔、任务用卡片，避免卡片层层嵌套。焦点和错误可见，成功用既有轻提示。数值与版本用等宽数字；长标题在详情完整可读。

## 交互约定

- 任务流转仅由 `availableTransitions()` 与 `transitionTask()` 决定；被阻塞说明来自真实依赖。依赖关系不新增第六个状态。
- 提交/重交填写完成说明、验证结果、成果文件或链接、逐项自检；打回填写未通过项与修改意见。每次提交新版本，原成果和意见不覆盖。
- 任务池、看板、表格共享 q/status/priority/assigneeId/milestoneId/labelId/blocked/groupBy。切换保留筛选，已选条件可清除；保存视图只保存合法条件，分享链接仍校验接收者权限。
- 看板/表格 `task=UUID` 打开共享详情；关闭只移除详情参数。保留触发焦点，任务不在当前筛选时仍明确当前筛选与详情来源。
- 资料通过 `resource=UUID` 深链接；来源的 `revision=N` 必须显示真实原版本，缺失时明确提示，不能以当前正文冒充。
- 目录调整先选名字和目标路径；禁止循环、越范围及超过子树最大深度。删除空目录先确认，不递归删除项目或资料。
- 正文评论可带真实引文、行号和内容版本；编辑、撤回、解决均有留痕。协作者评论/编辑与管理权限分别说明，管理不因收到链接而授予。
- @通过姓名选择器明确选成员；名字/版本快照保留。正文中手工输入 @ 文本不自动发消息。关注可取消，类别偏好与气泡设置可保存。
- 保存期间显示等待、防重复和关闭；失败保留正文、选择、附件与原版本。409 明确告知已有更新，用户核对并明确采用最新版本后才继续写入。
- 内容草稿按账号与对象隔离；浏览器保存失败显示可复制的提示。取消放弃需确认，按 Esc 与背景点击不得悄悄丢失正文。
- 多文件上传逐份显示等待/处理中/成功/失败，失败单独重试；不伪造上传百分比。讨论附件与正式成果分别选择，原文件仍在资料库。
- bot 与 AI 草稿互斥，详情/表单层级更高；真实未读角标、可收起气泡、点击直达事项。错误提供就近重试，不能填模拟通知。

## 响应式与可访问性

390px 视口先检验全页溢出，复杂表格和看板局部滚动，表单与目录上下排布。弹窗使用现有 Radix 焦点环路，标题/说明齐全，所有图标按钮有可读名称；关闭返回合理触发位置。正文对比度目标 4.5:1、关键焦点/边界目标 3:1，必须在实际深浅背景核验。动态消息使用 status，静态标签不全部播报。

## Agent 执行方式

先读 AGENTS 当前范围与 TEAM 契约，确认分支、基线、文件 Owner 和已有修改。每张派工说明写清问题、允许文件、提供/消费的公开入口、失败与权限要求、实际交付和验证。共享 schema、TEAM、版本由 root 串行集成；不让多位 agent 改同一文件。完成报告区分已实现、必要检查与未实施；历史概念稿不作为实装截图。
