# 个人日历与日程

个人日历位于 `/calendar`，从工作空间侧栏进入。个人安排由本人管理；项目日历继续显示团队任务截止与里程碑，不把个人安排加入任务状态机，也不向团队成员展示个人日程。

## 字段与使用

日程包含标题（100 字）、说明（500 字）、日期、可选起止时间和普通/重要/紧急优先级。日期为有效的 `YYYY-MM-DD`，范围 1900–2100 年；开始和结束时间为同一天的 `HH:mm` 本地钟表时间，不转换为 UTC。未填写时间表示全天，两项时间须同时存在且开始早于结束；跨日安排分别创建，不隐式挪动日期。

月历支持选择日期、前后月、返回今天、标题/说明搜索与优先级筛选；条件保存于 URL，刷新和后退可恢复。当天安排在侧栏显示，窄屏显示在月历下方。新建和编辑使用有标签的弹窗表单，保存失败保留输入；删除需确认，取消和 Esc 不写数据，关闭后焦点返回触发按钮。

保存成功后进入实际保存的日期并清除搜索/优先级筛选，使新安排可见；不通过前端提前移动或插入日程。提交期间不能重复提交或关闭弹窗，失败可以继续修改输入。

## 权限和并发

服务入口先验证账号存在。归属取自当前会话，输入不接受 `userId`、创建时间或版本覆盖；读取、修改和删除始终包含本人 `user_id` 条件。团队管理员也没有读取他人个人安排的权限，不需加入团队才能管理自己的日程。

日程使用递增 `version`。编辑和删除须提供当前版本；数据库单条条件写入同时检查用户、ID 与版本，旧页面或并发失败返回 409，不覆盖另一窗口已保存的内容。他人或已删除日程返回 404；未知参数、非法 JSON、日期和时间返回 400。没有新增日程状态，不改变五态任务验收规则。

## 接口

| 操作 | 路径与输入 | 成功 |
|---|---|---|
| 查询本人月日程 | `GET /api/v1/calendar/schedules?year=2026&month=10` | 200，`{ schedules }`，仅该自然月 |
| 新建 | `POST /api/v1/calendar/schedules`，日程字段 | 201，`{ schedule }` |
| 编辑 | `PUT /api/v1/calendar/schedules/:id`，`{ version, input: 日程字段 }` | 200，`{ schedule }` |
| 删除 | `DELETE /api/v1/calendar/schedules/:id`，`{ version }` | 204 |

字段名为 `title/description/scheduleDate/startTime/endTime/priority`；时间为空用 `null`，优先级用 0/1/2。路由只导出模块 API 薄壳；页面使用模块 Server Actions，均调用同一服务，成功后刷新 `/calendar`。查询结果 `private, no-store`，不缓存个人内容到共享缓存。原有 `GET /api/v1/calendar?projectId/year/month` 的项目日历契约保留。

查询限定当前账号和自然月，复用 `(user_id, schedule_date)` 复合索引；月历按日期一次分组，不逐格请求数据库。客户端公开 `calendar/client` 仅包含 DTO、Zod 校验及查询/排序纯函数，不加载数据库和会话。

## 数据升级

已有数据库执行追加迁移，原表和历史记录保留：

```powershell
node scripts/migrate-schedules.mjs
node scripts/migrate-schedules.mjs --test
```

迁移事务执行且可重复运行，只新增 `personal_schedules` 及索引和约束。新库使用既有 `db:push`。数据库同时约束标题、说明、日期、时间配对/顺序、优先级和版本，避免绕过页面后存入非法记录。

## 提供文档的取舍

本次核对用户提供的 `schedule.docx`、`script.js.docx`、`路由注测.docx`、`数据库建表.docx` 的全部文本。采用个人归属、标题/说明、日期/时间、三级优先级、月查询与 CRUD、登录保护、用户日期索引和创建/更新时间。

Java/MyBatis 实体、Vue 路由及请求封装、MySQL 自增 ID 与建表语法不直接移植；按现有 Next.js、Zod、Drizzle 和 PostgreSQL 契约实现。新增 UUID、用户外键、版本并发校验、全天与真实日期校验，不增加依赖、不调整登录。原文件仅作参考且不修改；不是部署脚本或授权依据。
