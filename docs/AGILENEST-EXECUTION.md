## 冻结决策与接口

- “任务”是侧栏入口，看板/表格页内切换；任务池保留独立入口、旧路由与自身语义。
- 详情抽屉最大 660px，手机全屏；复杂编辑、子任务和工时走完整详情。
- `TaskDetailSummary` 是只读展示，已登记工时可缺省，不把未加载当作零；`TaskActions` 和 `TransitionDialog` 继续承接合法操作。
- 拖动撤回认领或重新打开任务也使用操作确认框；取消后保持原列，不提前写入状态。
- 活动请求可取消、可重试，并按账号/任务/更新时间隔离；不引入通用评论或附件。
- 不实施 `task` query 深链接、任务池共享筛选或项目日历统一筛选。这些需要单独冻结数据与导航契约。
- 不修改登录、core、schema、依赖或任务状态机；Sprint、GitHub 同步、历史燃尽图和 AI 执行仍在路线图范围。

公开入口和具体 props 见 [TEAM.md](TEAM.md)。后续 agent 使用 [任务卡](AGILENEST-AGENT-BRIEFS.md) 派工，先核对当前分支与未提交改动，不重新创建已完成的容器或状态规则。

## 真实页面点验

在本轮本地开发服务中，用既有演示账号完成以下检查：

1. 全局工作台显示“选择项目”；进入项目后只显示一组项目导航。项目切换使用可键盘访问的菜单。
2. 多状态、多优先级 URL 恢复为“已选 2 项”；输入中文搜索后，两组值和分组保留；表格切换显示同一条结果，清除筛选仍保留分组。
3. 看板与表格使用同一详情抽屉；Esc 关闭返回原任务按钮，手机菜单关闭后返回打开按钮并退出可访问树。
4. 390px 页面没有整体横向溢出，表格和看板局部横滚；手机详情宽度约等于视口，底部操作区保持可见；手机菜单切回 1024px 桌面自动关闭。
5. 新建本地演示任务“体验迭代验收（rc.5 演示）”：创建 → 队员认领 → 提交 → 老师打回 → 队员重交 → 老师通过。输入后取消提交不改变状态或活动数量；重交保留旧意见和历史说明。
6. 队员进入验收台仅显示职责说明；老师看到待验收队列。打回/通过均清空该待验收项，工作台与状态同步。
7. 独立详情显示同一份成果、意见和 6 条真实活动；统计显示 3/7 已验收顶层任务、43%，下钻含同一个已完成演示任务。既有其他任务未修改。
8. 项目日历明确项目名称与个人安排入口；“开题”里程碑进入实际 `milestoneId` 筛选表格，显示 6/7 个关联任务。
9. 深浅主题和桌面/1024px/390px 入口已检查；验收用临时视口和主题在结束前还原。
10. 把已完成演示任务拖到进行中列，出现“重新打开任务”确认框；取消后仍在已完成列，焦点返回原拖动入口，完成度仍为 3/7。

本轮保留该演示任务及其活动以供复查，没有删除开发数据。并发认领、非法转移、父子验收限制、个人日程隐私/版本冲突由完整契约测试覆盖；未另做浏览器断网注入、屏幕阅读器或 Windows ZIP 重新打包验收。
