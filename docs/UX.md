## 后续体验验收标准

本节是重复执行的检查要求，**不是新增通过记录**。每轮报告注明提交、运行环境、实际步骤和未检项，不复用历史测试数量。

| 检查面 | 合格标准 |
|---|---|
| 入口与空状态 | 团队→成员→项目→任务→验收→交付路径可达；无数据与筛选无结果分别提供创建/加入或清除入口 |
| 权限 | 入口和服务端按相同职务/项目能力计算；学术身份不授权；本人日程隔离、最后管理员及成员归属保护成立 |
| 全态任务链路 | 带标准发布→认领/指派→执行→v1 提交→逐项打回→v2 重交→验收→合法重开；详情、活动与版本目标一致 |
| 非法操作 | 缺标准、缺证据/自检、旧版本验收、依赖/子任务未完成和非法转移有明确错误，输入和原列保留 |
| 资料与交付 | 就地多文件上传、逐份失败重试；主题路径、移动、引用保护与恢复正确；交付仅引用真实通过版本，未完清单/问题阻止确认 |
| 筛选与导航 | 看板/表格/任务池切换、刷新、返回保留 URL 条件；详情关闭只移除对应参数并恢复触发焦点 |
| 表单与并发 | 姓名选择负责人；等待防重复；取消/失败保留输入，版本冲突提示核对最新内容，不静默覆盖 |
| 键盘与窄屏 | 图标有名称，焦点可见，Tab/Esc/焦点返回完整；拖动有按钮等价入口；390px 下仅复杂内容局部滚动 |
| 主题与反馈 | 深浅主题文字、焦点和状态可辨；状态不只依赖颜色；减少动效生效；真实反馈与通知不伪造成功 |
| Windows 运行包 | 首装、旧库追加升级、重复启动、关闭/重启保留和维护停止分别验证，开发数据与包检查隔离 |

自动检查仍按 [WORKFLOW](WORKFLOW.md) 执行 `npm test` 和 Windows `npm run build`。无数据库时只能报告纯函数检查，不替代完整发布验收。
