# AgileNest 协作工作区与分步执行

更新：2026-10-11 · 发布目标：0.5.0 · 实施分支：`codex/v050-collaboration-release`

以飞书日常协作为主参考，GitHub 补充任务组织与研发证据。产品账号、资料和授权由本平台独立管理。当前源码能力、后续方案和已发布运行包分别记录，参考不代表外部连接或整仓复刻。

## 完整业务链路

| 阶段 | 入口与操作 | 可追溯结果 |
|---|---|---|
| 组织空间 | 团队资料、公告、成员职务、项目目录 | 当前成员/权限与项目归属 |
| 整理目标与资料 | 项目概览 → 资料目录 → 文档/文件 | 原文件、正文版本、引文评论、协作者 |
| 规划执行 | 创建任务或从文档/会议摘录创建行动项 | 来源版本、验收要求、负责人、标签、依赖与截止日期 |
| 协作反馈 | 任务详情 → 讨论/回复/附件/@成员 | 编辑/解决/撤回历史、成员提及快照与站内通知 |
| 成果提交 | 负责人提交/重交 | 完成说明、验证结果、证据、逐项自检与不可变版本 |
| 指定版本验收 | 具有验收职务的管理员/副管理员/指导老师核对每项 | 通过或打回意见，重交保留原版本 |
| 本人跟进 | 关注、保存视图、消息中心、本人日程提醒 | 个人偏好与事项直达；私人日程不向团队开放 |

资料库存放原件，讨论附件用于沟通，正式提交再次选择证据并绑定版本；三者互链但用途清楚。讨论解决与文档行动项不是任务验收。前置任务未验收时不能提交/重交/通过被阻塞任务。

## 0.5.0 执行范围

用户指出资料分类和目录入口割裂、右下角有重复图标，并明确研究、课程、竞赛和混合项目不必以代码为中心。本轮将 R6 从“研发补充”改为“通用协作与交付”，GitHub 保留为可选成果链接；不以外部同步作为通用业务的完成条件。

| 步骤 | 可执行交付 | Owner 与完成条件 |
|---|---|---|
| 1 资料组织 | 分类内新建主题 → 多层子文件夹 → 按当前位置创建/上传 → 移动与路径 | resources；同空间同分类、旧目录兼容、版本冲突保留输入 |
| 2 R5 交付完善 | 阶段责任人/日期/检查项、绑定真实通过版本、评审问题处理、完成记录、归档/恢复、Markdown/JSON 导出 | tasks/delivery；不覆盖提交历史，未解决问题和未验收成果阻止阶段确认 |
| 3 R6 通用协作 | 合并消息与 AI 草稿为一个右下角入口，真实未读与分类；项目路径串联资料、执行、验收、阶段交付 | foundation/notify UI；模型未接入，项目无需 GitHub 账号 |
| 4 资料回收 | 可恢复回收站、原文件保留、当前列表/预览隔离、引用证据禁止回收 | resources；恢复同一资料及历史，未做永久清除或自动过期 |
| 5 R7 综合验收 | 五种叠加职务、越权、并发旧版本、任务提交/打回/重交/验收、目录回收、深浅主题、窄屏键盘、旧库升级和独立运行包 | root 串行数据库与构建；实际结果登记 UX/CHANGELOG，失败项修正后复验 |
| 6 正式发布 | 合入 main → 最终测试/Windows 构建 → 0.5.0 元数据与 tag → 自带运行时 ZIP/SHA256 → GitHub Release | root；只发布本轮 tag，不覆盖历史 Release 或打包个人 data/.env |

完整多人实时编辑、独立群聊/通信、外部 GitHub/飞书同步及模型调用不属于 0.5.0，独立方案仍保留。当前进度以实际提交与检查记录为准。

| 资料组织 | 八层文件夹、子树移动校验、位置/置顶、分类/范围/类型/关键词筛选 | 团队共享与项目资料明确；文件原件不可覆盖 |
| 内容互链 | 资料↔资料、同项目资料↔任务、反链与来源 | 关联目标逐项检查权限，分享链接不扩权 |
| 内容评论 | 引文/行号/正文版本、单层回复、编辑/解决/撤回/历史、@快照 | 原版本真实展示；缺失时明确提示，草稿按账号隔离 |
| 协作者 | 每份资料评论/编辑授权，评论范围 team/collaborators | 当前团队成员可读；作者/管理员管理授权，edit不等于manage；未实现“仅选定成员可读” |
| 任务组织 | 项目标签、标签选择、双向依赖、名称选择与可解释阻塞 | 同项目 DAG、版本冲突、删除保护与合法状态守卫 |
| 文档/会议行动项 | 真实摘录创建任务、稳定请求键、来源版本与回链 | 会议记录作为项目文档；同事务保存任务/事件/来源，无独立会议日程模型 |
| 讨论 | 正文/原文件、回复、历史、分页、旧通知定位、提及与关注 | 编辑作者本人；处理权限按任务/职务；附件与提交版本分别选择 |
| 本人保存视图 | 按本人/项目保存名字、布局、分组与合法筛选；改名、删除与版本 | 私人保存项不对团队共享；分享继续使用筛选 URL，失效标签保留条件 |
| 站内通知 | 提及、参与、事项/项目关注、去本人、去离队、事件幂等、已读 | 取消事项关注覆盖项目继承；类别关闭不回放旧事件 |
| 个人通知偏好 | 任务、讨论、提及、资料、提醒类别与 bot 气泡持久化 | 偏好关闭不删除已收到消息；UI真实失败反馈 |
| 本人提醒 | 日程版本+提醒版本、提前量、全天北京时间09:00、24小时内补发 | 页面可见时60秒刷新或返回时检查；关闭网站不会系统推送；仅本人日程 |
| 成果与验收 | 原有结构化提交、不可变版本、逐项指定版本验收与意见 | 前置依赖和子任务守卫同时成立；通过不等于外部PR已合并 |

本轮协作数据追加22张表与独立迁移，旧任务、文件、提交与日程保留。升级执行 `node scripts/migrate-collaboration-foundations.mjs`，测试库加 `--test`。用户后续要求副管理员职务，对既有 `team_position` 枚举仅末尾追加 `deputy`，另运行 `node scripts/migrate-member-deputy.mjs`；不改旧迁移或既有成员职务。新库初始化使用当前schema；发布包迁移列表已登记，本轮没有制作或发布新的Windows ZIP。

## 执行分工与交付顺序

| 顺序 | 内容 | Owner/范围 |
|---|---|---|
| 1 冻结 | 当前范围、追加表、权限、通知目标、版本与幂等 | root/foundation；AGENTS、TEAM、schema |
| 2 并行业务 | 知识库协作；标签/依赖/行动项；关注/偏好/本人提醒 | resources；A/tasks；E/notify/calendar |
| 3 界面整合 | 项目目录、讨论提及/分页、共享详情；统一筛选与保存视图 | foundation/identity；C/root；B/root委托代理 |
| 4 集成验证 | 追加迁移、必要真实数据库契约、类型/模块边界、Windows生产构建 | root串行；成员不同时重置测试库 |
| 5 文档与候选 | 更新当前事实、删失效计划、同步版本与实际检查记录 | root；不标正式版或覆盖历史tag |
| 6 最终综合验收 | 用户给出最后要求后覆盖完整多角色、多端、升级与运行包 | root与对应Owner |

公开签名与消费方式以 [TEAM](TEAM.md) 为准；视觉/交互执行标准见 [设计指南](FRONTEND-DESIGN-GUIDE.md)。root可接续已登记模块的集成遗漏，不切换或覆盖成员分支。

## 实时共同编辑独立方案（未实施）

先建立文档编辑会话、参与者权限、内容版本与操作审计；保留现有文档快照作为发布/来源版本，不把实时草稿直接作为验收证据。采用CRDT或服务端操作同步前需在已授权范围核对依赖/许可证与Windows运行环境，不在现有长文表单上伪造其他成员光标。

会话握手由当前账号与文档ACL计算编辑权，连接建立和每批写入均复核；移除成员或撤销编辑权立即停止写入。消息包含docId/sessionId/clientId/sequence/baseRevision，服务器去重并保存可重放的操作。重连先协商服务器序号/快照再补发离线队列，禁止把旧全文覆盖新内容。断网明确“未同步”，并为无法恢复的本地草稿提供复制/导出。

限定每文档参与人数、操作大小、速率与保留期限；定期快照、清理操作必须保留来源版本。上线前分别验证并发输入、撤权、重复/乱序、断网重连、长文性能与数据恢复。落地时需另登记Owner、公开接口、迁移和依赖批准，不沿用普通编辑409当作实时协议。

## 群聊与在线通信独立模型（未实施）

基础实体拟为 conversation、conversation_member、message、message_revision、attachment_reference、per_user_read_cursor；频道/私聊的成员关系单独授予可见权，团队管理员不自动读取私人会话。消息发送用clientRequestKey幂等，编辑/撤回保存历史，附件保留当前访问权，@收件与类别偏好复用已实现通知契约。

在线连接使用短期会话身份和conversation订阅检查；服务器广播只向当前成员投递，移出会话终止订阅。离线补取使用稳定序号，已读游标只属于本人。在线状态与正在输入设置过期时间，不作为永久业务事实；未读不依赖某设备的内存计数。搜索、留存、导出、撤权与附件下载的范围先明确。

先做真实异步消息与离线同步，再另验WebSocket/流式传输、部署和故障恢复。视频/语音、企业邮箱、飞书投递、系统Web Push不以聊天外观冒充；这些运行能力分别立项。
