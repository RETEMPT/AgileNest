# AgileNest 协作空间与后续迭代

更新：2026-10-10 · 源码候选目标：0.4.0-rc.7 · 分支：`codex/collaboration-workspace`

## 产品方向

用户最新要求：尽可能全面、分多轮覆盖常见协作能力，以飞书的日常协作为主参考，GitHub 补充研发协作。先让成员理解从项目资料、任务分工、讨论执行到成果验收的关系，再扩展知识库、消息与代码集成。平台账号、权限与数据仍独立于飞书和 GitHub；参考界面不等于连接外部账号或复制整个产品。

## 一条明确的协作流程

| 阶段 | 谁操作 | 在哪里 | 留下什么 |
|---|---|---|---|
| 资料与目标 | 协调者与成员 | 项目概览 → 项目资料库 | 目标、需求文档、参考文件 |
| 任务分工 | 协调者指派、执行成员认领 | 任务池或看板 → 任务详情 | 负责人、截止日期、验收要求 |
| 讨论与执行 | 项目成员与任务负责人 | 任务详情 → 讨论与任务附件 | 问题、回复、执行材料、实际工时 |
| 成果提交 | 任务负责人 | 提交或重交面板 | 完成说明、验证结果、附件/链接、自检快照 |
| 验收与交付 | 管理员或指导老师 | 验收台或任务详情 | 绑定指定提交版本的逐项结论 |
| 修改重交 | 原负责人 | 打回记录 → 待修改任务 | 新成果版本，保留原成果和意见 |

**资料、任务附件和提交成果是三个用途。** 原文件实际保存于团队/项目资料；讨论引用文件用于沟通，不改变状态；正式提交需要再次明确选择成果证据，将原文件、说明和验收项绑定到本次版本。重交不覆盖旧提交。讨论解决也不会把任务标记为完成。

## 本轮落地范围

- 项目概览加入五步协作路径、真实状态数量和按本人职务计算的下一步入口，复用已有顶层任务查询。团队项目卡片优先进入概览，保留看板快捷入口。
- 任务完整页与详情抽屉加入讨论：正文/附件、单层回复、编辑版本、历史、撤回留痕、主题解决与重开。作者编辑本人内容；管理员可撤回他人内容；根作者、任务负责人或验收职务可解决讨论。
- 讨论文件仅关联当前项目或同团队共享文件；保存真实元数据，编辑不能换附件，撤回后保留引用与历史，避免原文件被删除。
- 附件选择支持多文件及拖入，逐文件显示等待/上传/成功/失败，失败单独重试，已有成果选择保留。原文件单份 10 MB、每条讨论/每次成果提交最多 10 份；没有伪造上传百分比。
- 资料库显示团队共享/项目专属，分类、类型、范围、关键词和详情写入 URL；`?resource=UUID` 可以分享给有权限的成员，复制链接不改变权限。关闭详情保留筛选，失败可重试。
- 右下角协作助手呈现真实站内通知、完整本人未读数、单条/全部已读及事项直达；与 AI 本地草稿入口整合为互斥面板。可见页面定期更新，重新聚焦刷新，不宣称已接入系统 Web Push、飞书私信或模型。
- 任务新讨论通知任务负责人，回复同时通知根讨论作者，排除本人；通知与新讨论同事务保存，不向离队成员投递。

## 后续执行顺序

每轮先冻结数据、权限和公开入口，再按 Owner 落地页面与状态反馈，最后记录实际检查。完整多角色/多端/发布包综合验收仍按用户要求在迭代接近结束时集中进行。

| 轮次 | 优先能力 | 关键交互与完成条件 | Owner |
|---|---|---|---|
| R1 当前 | 项目路径、讨论/附件、资料范围与通知助手 | 能从概览找到入口，发布讨论与附件，查看历史，并从真实消息到任务 | foundation / resources / discussions / A / E |
| R2 协作反馈 | @成员、关注任务/讨论、未解决事项、讨论历史分页 | 从成员选择器提及，不输入 ID；只通知可见对象；关注可取消，断网/失败保留输入 | discussions / notify / identity |
| R3 项目知识库 | 文件夹/目录、置顶、资料与任务互链、文档评论、归档/回收 | 找资料有目录和搜索，引用与版本有来源；删除/恢复不破坏提交证据 | resources / foundation |
| R4 工作组织 | 任务标签/类型、依赖与阻塞、清单、保存视图、会议行动项与日历 | 阻塞关系可解释、无依赖环；同数据视图保持条件；行动项变成真实任务 | A / B / calendar / notify |
| R5 交付管理 | 项目阶段材料、评审意见处理、交付清单/发布记录、导出 | 每份交付可追溯到通过的成果版本与责任人；项目归档保留历史 | review / milestone / resources |
| R6 研发补充 | GitHub 仓库归属、只读分支/Commit/PR、差异与检查结果、任务关联 | 外部授权和可见范围先明确；处理撤权、过期结果与重复事件；状态不由页面伪造 | 新 integration Owner / A / review |
| R7 综合验收 | 最终范围的角色、并发、旧数据升级、多端、键盘与发布 | 用户给出最终要求后统一验收；修正、合入主分支、验证后才正式发布 | root / 各 Owner |

R2–R6 是后续执行范围，不是已经实现的页面承诺。实时多人文档编辑需要独立并发同步方案；视频会议、企业邮件、Git 托管服务器、CI 执行器和安全扫描运行时不由本轮轻量界面冒充。若确需覆盖，分别建立数据/运行环境/权限方案；现有依赖锁定及 core/登录约束继续适用。

## 参考能力与当前差距

| 参考能力 | 当前 AgileNest 状态 | 继续补齐 |
|---|---|---|
| 飞书团队与成员 | 团队、可叠加职务、资料、公告、邀请 | 项目空间目录、关注与通知设置 |
| 飞书云文档/知识库 | Markdown 文档、历史、原文件与权限下载 | 目录、互链、内容评论、协作者权限；实时共同编辑另立方案 |
| 飞书任务与讨论 | 五态任务、子任务、指派、讨论、附件、工时 | 标签/依赖、@提醒、关注、文档行动项 |
| 飞书消息协作 | 本人消息中心与右下角通知助手 | 订阅与提及、通知偏好；群聊与在线通信另立模型 |
| 飞书日程 | 本人日历与项目排期、里程碑 | 会议行动项、本人提醒、统一筛选；他人私人日程保持隔离 |
| GitHub Issues/Projects | 任务、子任务、负责人、里程碑、看板/表格筛选 | 标签、类型、阻塞、保存视图和历史分析 |
| GitHub PR/Review | 手工代码成果链接、不可变提交、逐项验收与意见 | 仓库/PR 实时信息、代码差异和行评论；验收通过不等于代码已合并 |
| GitHub Wiki/Releases | 项目资料和成果版本 | 目录文档与正式项目交付/发布记录 |
| GitHub Actions/Rules/Security | 未接入 | 先显示真实外部检查结果；执行器与安全能力另立方案 |
